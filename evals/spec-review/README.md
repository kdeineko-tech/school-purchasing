# Eval скіла `spec-review` (WS8, бонус)

Чи допомагає скіл `.claude/skills/spec-review` знаходити проблеми перекладу вимог PM у специфікацію? Однакові кейси —
зі скілом і без, по 3 прогони, свіжа копія фікстури на кожен прогін (шлях 3 з гайду курсу: цикл `claude -p`,
https://github.com/koldovsky/2026-quitcode-08-quality-hw/blob/main/docs/gates-guide.md#бонус-eval-свого-скіла).

- **Кейси** — `cases/<кейс>/fixture/` (вимога PM, «Продукт», шапка матриці, `proposal.md`, дельта специфікації вигаданого
  порталу відпусток) з однією посадженою проблемою; `cases/<кейс>/expect.json` — що має бути у відповіді.
- **Зі скілом:** у копію кладемо `.claude/skills/spec-review` і таксономію з `spec-clarify`, запит `/spec-review add-leave`.
  **Без скіла:** скіла в теці немає, запит «Перевір зміну специфікації add-leave … проти вимог PM у requirements/ перед PR
  «Специфікація» і дай список знахідок».
- `claude -p` з моделлю `claude-sonnet-5-5`, лише `Read`, `Grep`, `Glob`, `--setting-sources project`; оцінка — регулярні
  вирази з `expect.json` (усі мають збігтися).
- Запуск у звичайному терміналі: `npm run eval:spec-review` (усі кейси) або `npm run eval:spec-review -- --runs 1 --case 4-hidden-ac`.
  Результат — `results/report.md` і `results/results.json` (відповідь кожного прогону).

## Висновок

- **На знаходженні цих 4 проблем скіл різниці не дав: 12/12 і 12/12 (Δ = 0).** Кейси виявились легкими для
  `claude-sonnet-5-5` — навіть кейс 4 (AC у HTML-коментарі), на який ми розраховували як на «правило лише зі скіла»,
  модель без скіла знайшла 3 з 3 (за текстом «PM: чернетка, ще не узгоджено» поруч).
- **Що скіл додає — процес і форму:** класифікацію серйозності й БЛОКЕРи, звірку ID PM ↔ сценарії, нагадування про
  детерміновані перевірки, питання до PM замість правок — 12/12 проти 0/12. Ціна — ≈1,5× часу й вартості.
- **Наступний крок eval:** складніші кейси, де правило є лише в скілі — AC без ролі, перейменований AC ID, два AC з одним
  ID, MODIFIED, що губить сценарій, — і слабша модель (Haiku), де різниця, ймовірно, з'явиться. Оцінка регулярними
  виразами груба: вона підтверджує згадку, а не якість пояснення; для тонших кейсів — LLM-оцінювач.
